## 2. Remediation Analysis: Silent Model Substitution Eliminated

### Root Cause of Previous Contamination Risk
Prior to this remediation, `BaseAgent.generate_and_validate_thesis()` caught HTTP exceptions from OpenRouter (such as HTTP 402 Payment Required) and silently substituted the heuristic baseline's `stock_data.get("predicted_1d_pct")`. This created a critical institutional defect:
1. The prospective study would record trades attributed to OpenRouter that were actually generated by local heuristics.
2. An outage or payment lapse could produce either contaminated positions or inaccurate prediction loss metrics.

### Institutional Remediation Architecture
The silent fallback has been completely dismantled. The system now enforces a strict **two-path decoupled architecture**:

```
                    ┌───────────────────────────┐
                    │ OpenRouter LLM Inference  │
                    └─────────────┬─────────────┘
                                  │
                   ┌──────────────┴──────────────┐
                   │                             │
                SUCCESS                       FAILURE
                   │                     (HTTP 402, 429, 503)
                   ▼                             │
          INFERENCE_SUCCESS                      ▼
                   │                       AI_UNAVAILABLE
                   ▼                             │
             MarketThesis                        ▼
                   │                          NO_TRADE
                   ▼                             │
            ThesisValidator                      ▼
                   │                  InstrumentSelector Gate 0.0
                   ▼                             │ (Zero Risk / Proposal Dropped)
          InstrumentSelector                     │
                   │                             ▼
                   ▼                     TradeGuard Gate 35
              TradeGuard  ◄──────────────────────┘ (Independent Authorization Veto)
                   │
           Gates 1-35 Passes?
                   │
          ┌────────┴────────┐
          │                 │
         YES                NO
          │                 │
          ▼                 ▼
     ORDER INTENT        NO ORDER (Entries = 0)
```

Meanwhile, the **Existing Position Protective Exit Path** runs completely independently:

```
EXISTING POSITION PATH (Deterministic Broker Safety)
Broker Open Positions
         │
         ▼
    ExitEngine (Pure deterministic rules, Zero LLM dependency)
         ├── Target Hit (+0.10% net gain)  ──► ExitSignal(TARGET)
         ├── Stop Loss Hit (or -3.0% loss) ──► ExitSignal(MAX_LOSS)
         ├── Regime Volatility Transition ──► ExitSignal(THESIS_INVALIDATED)
         └── Normal monitoring within range ─► Continue monitoring

INVARIANT: AI outage NEVER disables broker-side protective exits.
```

## 3. Verification of the 5 Institutional Modifications

### Modification 1: Fail-Closed Behavior for New Entries
- When OpenRouter returns HTTP 402, 429, or network failure, `generate_decision_thesis()` returns `status="FAILED"`, `ai_status="CREDIT_EXHAUSTED"`, `decision_mode="AI_UNAVAILABLE"`, and `direction="NO_TRADE"`.
- `BaseAgent.generate_and_validate_thesis()` refuses to touch `predicted_1d_pct` and constructs a non-trading thesis tagged `evaluation_status="EXCLUDED_FROM_ACCURACY"`.
- Verified in: `test_openrouter_decision_thesis_402_returns_ai_unavailable` and `test_base_agent_refuses_silent_heuristic_fallback`.

### Modification 2: AUTHENTICATED is NOT Permission to Trade
- `OpenRouterStatus.AUTHENTICATED` indicates that a credential health check succeeded, but does **not** indicate a successful decision inference.
- TradeGuard Gate 35 explicitly enforces:
  $$\text{Gate 35 PASS} \iff \text{ai\_status} == \text{"INFERENCE\_SUCCESS"}$$
- If `ai_status` is `AUTHENTICATED`, `CREDIT_EXHAUSTED`, `RATE_LIMITED`, `INFERENCE_FAILED`, or `UNAVAILABLE`, Gate 35 fails closed with `TRADE_BLOCKED_AI_UNAVAILABLE`.
- Verified in: `test_authenticated_is_not_permission_to_trade`.

### Modification 3: Raw Provider Error Preservation with Secret Sanitization
- Structured status codes (`CREDIT_EXHAUSTED`, `RATE_LIMITED`, `UNAVAILABLE`) are preserved alongside the exact HTTP error code and message.
- `sanitize_secret_error()` parses and redacts all instances of `sk-or-v1-...`, `sk-live-...`, and `Bearer ...` tokens before recording to ledger or telemetry tables.
- Verified in: `test_openrouter_402_maps_to_credit_exhausted_and_sanitizes_secrets`.

### Modification 4: Cohort Integrity Invariant (`test_ai_failure_cannot_enter_prospective_cohort`)
- End-to-end verification proving:
  1. OpenRouter 402 triggers `CREDIT_EXHAUSTED` and `AI_UNAVAILABLE`.
  2. `decision_id` is logged for auditability, but action is `NO_TRADE`.
  3. No `order_intent_id` is created.
  4. No `broker_order_id` is sent to any execution venue.
  5. No new position is created.
  6. Ledger reconciliation ignores the record (`evaluation_status="EXCLUDED_FROM_ACCURACY"`), ensuring the AI outage day is **never** penalized as a 0% predictive accuracy day.
- Verified in: `test_ai_failure_cannot_enter_prospective_cohort`.

### Modification 5: Operational AI Availability Metrics Tracking
- System availability is cleanly decoupled from model predictive quality:
  $$\text{Model Quality} = \frac{\text{Correct Predictions}}{\text{Evaluated Predictions}}$$
  $$\text{System Availability} = \frac{\text{Successful AI Decisions}}{\text{AI Decision Attempts}}$$
- `OpenRouterMetricsTracker` records and exposes:
  - `AI_DECISION_ATTEMPTS`
  - `AI_SUCCESSFUL_DECISIONS`
  - `AI_UNAVAILABLE_DECISIONS`
  - `AI_CREDIT_EXHAUSTED`
  - `AI_RATE_LIMITED`
  - `AI_INFERENCE_FAILED`
  - `AI_AVAILABILITY_PCT`
- Verified in: `test_ai_availability_metric_decoupled_from_accuracy`.

## 4. Architectural Redundancy: Gate 0.0 vs Gate 35

| Component | Gate Identifier | Scope & Mandate |
| :--- | :--- | :--- |
| **InstrumentSelector** | Gate 0.0 | Prevents an invalid, failed, or missing thesis from ever translating into a financial instrument proposal or allocating risk capital. |
| **TradeGuard** | Gate 35 | Serves as the independent final safety authority. Even if upstream code accidentally constructed an active order proposal, Gate 35 vetoes authorization. |

Verified in: `test_instrument_selector_gate_0_blocks_ai_unavailable` and `test_tradeguard_gate_35_independent_redundancy`.

## 5. Strengthened Existing Position Exit Verification

During an AI provider failure, existing positions must not be trapped. The test verifies four simultaneous conditions:
1. **Target Hit**: Position with $+12\%$ gain triggers `ExitSignal(TARGET)`.
2. **Stop Loss Hit**: Position breaching stop level triggers `ExitSignal(MAX_LOSS)`.
3. **Thesis Invalidated**: Market transitioning to extreme macro volatility triggers `ExitSignal(THESIS_INVALIDATED)`.
4. **Normal Monitoring**: Position within bounds continues active monitoring with zero spurious exits.

Verified in: `test_existing_position_exits_continue_during_ai_outage`.
